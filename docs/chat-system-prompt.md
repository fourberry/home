## 요약

홈페이지 채팅 창(plum 공개 채팅)의 **고정 시스템 프롬프트 원본**입니다. 이 글은 사람이 plum 관리 화면(콘솔 "웹 채팅" 탭)의 홈페이지 설정에 붙여 넣습니다.
홈페이지 코드는 이 파일을 읽지 않으며 번들·생성 HTML에 들어가지 않습니다. plum은 이 글만 갖고, 홈페이지에서 자료를 읽어 가지 않습니다(plum 계획 결정 17).

방문자가 프롬프트를 꺼내 볼 수 있다고 보고 **공개해도 되는 것만** 씁니다. 출처는 이 저장소의 `data/` 정본과 공개 페이지뿐입니다.

## 갱신 절차

1. **언제:** 아래 출처의 사실(회사 정보, FAQ, 솔루션·도구 설명과 상태, 실적의 수행 주체·기간, AI 활용 방식, 연락처)이 바뀌는 PR에서 이 파일도 함께 고칩니다.
   출처: `data/company.ts`, `data/faq.ts`, `data/solutions.ts`, `data/coconut.ts`, `data/linkberry.ts`, `data/projects.ts`, `data/aiWorkflow.ts`, `pages/services/si-sm.vue`, 홈 섹션(`components/fb/`)의 공개 문구.
2. **규칙:**
    - 한국어 12,000자(유니코드 코드 포인트) 이하. 아래 "프롬프트 본문" 블록 안의 글만 셉니다.
    - 홈페이지 FAQ(`data/faq.ts`)의 질문·답은 같은 문구로 둡니다. 다른 자료는 뜻을 바꾸지 않고 줄입니다.
    - 확인되지 않은 사실은 채우지 않습니다. 개발 중·베타 제품은 상태를 적습니다. 구성원의 이전 회사 경력과 포베리 실적을 구분합니다.
    - 비공개 프로젝트명, 내부 경로·호스트·IP, 정책 원문, 비밀값, 사람 연락처(공개한 대표 전화·이메일 말고)를 넣지 않습니다.
    - 버전 번호처럼 자주 바뀌는 값은 넣지 않고 페이지 경로로 안내합니다.
3. **검사:** `node scripts/check-chat-prompt.mjs` — 글자 수, FAQ 문구 일치, 금지 패턴(내부 경로·IP·http 주소·다른 이메일)을 봅니다.
4. **넣기(사람):** `node scripts/check-chat-prompt.mjs --print`로 본문만 꺼내 plum 콘솔 → 웹 채팅 → 홈페이지 설정 → 시스템 프롬프트에 붙여 넣습니다.
   저장하기 전에 콘솔의 시험 상자로 아래 "시험 질문"을 보내 지어낸 사실이 없는지, 문의 폼 안내와 답 길이가 맞는지 봅니다. 그다음 저장합니다(다음 요청부터 적용).
   명령줄로 넣을 때는 플랫폼 관리자가 `plum webchat set <공개 ID> --prompt-file -`에 표준 입력으로 넣습니다.
5. **기록:** 아래 "넣은 기록"에 날짜, 이 저장소의 커밋, 넣은 사람을 적습니다. 홈페이지 배포와 프롬프트 반영은 따로 일어나므로 둘을 맞췄는지 이 표로 확인합니다.

- 없는 것: 삼성전자와 일한 적이 있나요? / 직원은 몇 명인가요?
